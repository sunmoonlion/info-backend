# Info 公共可靠投递

基于模板 `tpl-backend@b667a41` 的公共 DurableDelivery/DurableTasks。采集、索引与
分发通过 `delivery_handlers.py` 注册三个领域 topic；领域状态与命令同事务提交。
公共文件沿用模板；领域处理器、迁移与业务服务是 Info 扩展。

## 运行语义

Scheduler 每 5 秒触发公共 pump，负责发布、超时对账与有限重试；Worker 使用
消息 UUID 读取数据库意图，执行租约、epoch 和提交前 fencing，完成后记录 Inbox。
成功发布不代表成功消费。死信与重放入口为 `python -m app.cli.durable_delivery`。
旧 `drain_delivery_outbox --limit=100` 保留兼容；其他 limit 明确报错，不静默忽略。
旧 `DELIVERY_OUTBOX_*` 五个配置项已撤下，应从部署环境中移除。公共实现当前使用
每批 100 条、60 秒租约和最多 10 次投递；公共重试/对账策略以模板代码为准，
不能再使用旧配置名宣称调参生效。

- 采集 `enqueue=false` 只建单，`run` 路由只请求排队；失败作业的显式请求创建新代次。
- 成功/失败终态的同一轮重复消息不访问网络。执行取消或租约丢失保留可恢复进度，
  不生成终态或 Inbox。
- 搜索重建返回 `queued`，并保持 `indexed=0`；索引完成发生在 Worker。
- 分发重试保持稳定的 Knowledge 请求身份；响应丢失后依靠提供方幂等受理恢复。
- 对象存储和索引使用稳定对象键/版本标识；公共消费者不承诺任意远端副作用原子性。

## 迁移与回滚

迁移 `20260911_0007` 接在 `20260811_0006` 后，由独立 Migration Job 执行。
升级前停止旧投递者，备份并实际恢复验证；DBA 预置 `uuid-ossp`。迁移保留旧消息 ID，
已完成消息补 Inbox，旧分发表改名为 `delivery_outbox_message_legacy` 保留历史。
旧表名写入随即失败；新投递只有公共 Outbox 一个真源。

历史 running 采集补排队；历史 pending 作业无法证明原 enqueue 意图，不能批量猜测
启动。运营应逐项核对需要执行的作业，通过既有 `run` API 显式请求。保留版本的搜索
命令会被补齐；索引是可重建派生数据。

回滚前停止接单及调度，完成/处置在途命令和死信，核对业务状态、Outbox 与 Inbox，
再运行降级。存在未确认领域命令时降级拒绝，不能通过伪造 Inbox 绕过。
降级把已确认旧分发回写历史表后恢复旧表名；新消息及回执仍保存在公共基础表。
无法安全排空时使用经验证的整库备份恢复程序，记录回滚窗中新请求的处置。

## 本地验证边界

本轮在既有 KIND/PostgreSQL 的独立测试库验证；浏览器配对用仓内后端夹具。
另以真实 Casdoor 验证 Admin/Web 登录、会话隔离、CSRF 与退出，回调截获交给候选
进程内 ASGI，未替换在线 API，不等于完整部署态前后端验收。网络边界在独立 Calico
v3.28.2 集群验证放行与拒绝路径，首次失败后的完整重跑通过，初次原因未证实。
最新结果和未完成项见工作区根 `durable-delivery-progress-luna.md`，不得把旧镜像或
旧测试结果冒充本次正式发布。
